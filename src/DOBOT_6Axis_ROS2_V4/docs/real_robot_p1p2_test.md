# 실물 CR7 p1↔p2 pick-place 리허설 — 사용법과 설계

2026-08-06. 그리퍼가 아직 없는 상태에서 **CBiRRT로 물건을 집어 다른 곳에 놓는
동작 전체**를 실물에서 검증하기 위한 도구. 잡는 대신 접촉까지 하강해 3초 머무는
것으로 대신한다. `sequences/wirebonder_pick_place.py`의 guarded place와 같은 흐름.

**먼저 읽을 것**: `real_robot_joint_convention.md` — URDF와 컨트롤러의 관절 부호가
다르고, 그걸 모르면 팔이 거울 반전된 자세로 간다. 이 도구는 그 수정을 전제한다.

관련 파일:

| 경로 | 역할 |
|---|---|
| `test/cbirrt_p1p2_test.py` | 본체 |
| `test/run.sh` | 컨테이너 안에서 위 스크립트를 실행하는 래퍼 (호스트에서 실행) |
| `test/jog_bringup.sh` | 터미널 A/B + 조그 통합 실행, 상태 확인, enable, 에러 해제 |
| `test/points.json` | 교시된 p1 / p2 / home |
| `test/surfaces.json` | 교시된 책상·선반·벽 |

---

## 1. 한 사이클이 하는 일

```
p1 접근        (빈 손)   툴 자세가 이미 맞으면 CBiRRT, 아니면 자유 RRT
p1 하강                  접촉까지, 3초 대기, (내려간 만큼 + clearance) 상승
p1 → p2 운반   (적재)    CBiRRT, 툴 자세 고정 ← 물건을 든 구간
p2 하강                  접촉까지, 3초 대기, (내려간 만큼 + clearance) 상승
home 복귀      (빈 손)   home이 없으면 p1으로
```

상승량은 **명령한 값이 아니라 FK로 실측한 하강량** + `--clearance`다. 로봇이
명령을 거부했거나 컨트롤러가 스스로 후퇴한 경우 둘이 다른데, 명령값으로 올리면
출발했던 곳보다 그만큼 위로 솟아버린다. `--clearance` 기본값은 20 mm이고,
운반 구간을 높게 지나가려면 키우면 된다(예: `--clearance 0.12`).

운반 구간만 엄격한 CBiRRT다. 물건이 물려 있는 구간이므로 툴 자세를 고정해야
한다. 빈 손 구간은 `approach()`가 처리하는데, 가능하면 같은 CBiRRT를 쓰고 툴을
크게 돌려야 할 때만 구속 없는 관절공간 RRT로 내려간다.

## 2. 준비

### 2.1 브링업

터미널 A(로봇 TCP/IP 연결)와 B(`FollowJointTrajectory` 서버 + `/joint_states`)가
필요하다. `jog_bringup.sh`가 없는 것만 띄운다.

```bash
S=~/dobot_ws/src/DOBOT_6Axis_ROS2_V4/test/jog_bringup.sh
T=~/dobot_ws/src/DOBOT_6Axis_ROS2_V4/test/run.sh

$S --status        # 뭐가 떠 있는지, 로봇 상태까지. 아무것도 안 건드림
$S --enable-only   # A/B 올리고 로봇 enable, 조그 없이 종료
```

**`UP x2 <<< DUPLICATE`가 보이면 반드시 정리할 것.** 액션 서버가 둘이면 goal 하나를
양쪽이 받아 각자 `ServoJ`를 쏘고, 팔이 튀면서 충돌 트립이 난다. 조그 버그처럼
보이지만 아니다.

```bash
$S --stop          # 전부 종료 후 한 세트만 다시 띄울 것
```

### 2.2 조그

```bash
$S --real --speed 5    # tools/jog_real.py — MoveJog, TCP 직교 조그 가능
$S --speed 5           # tools/jog_action.py — 게임패드 4관절 동시, 관절 전용
```

`jog_real.py`가 툴을 수직으로 맞추기 편하다(`m` 키로 TCP↔JOINT 전환, `u/j i/k`로
Rx/Ry). 로봇 본체의 드래그 버튼으로 손으로 옮겨도 된다.

교시 명령은 로봇을 **읽기만** 하므로 조그를 켜둔 채 다른 터미널에서 실행해도 된다.

## 3. 교시

### 3.1 면 (책상·선반·벽)

URDF는 방이 존재한다는 걸 모른다. 각 경계면을 재서 **어떤 팔 링크도 넘을 수 없는
반평면**으로 충돌 모델에 등록한다.

방향은 **로봇 베이스에서 그 면을 향하는 방향**을 축 먼저 쓴다 (`z-`, `y+`, `x+`).
축을 먼저 쓰는 이유는 argparse가 `-z`를 값이 아니라 플래그로 읽기 때문이다.

**접촉해서 재기** — 툴을 면에 대고:

```bash
$T --teach-surface z- --name base_support --bound y -0.34 inf
$T --teach-surface z- --name low_shelf   --bound y inf -0.34
```

**수치로 지정** — 아직 세우지 않은 벽이나 도면 값:

```bash
$T --set-surface y+ --at 0.55 --name wall_y
$T --set-surface x+ --at 0.36 --name wall_x
```

`--bound`가 단차를 표현한다. 위 예에서 지지대는 `y ≥ -0.34`에만, 낮은 선반은
`y ≤ -0.34`에만 존재한다. 두 박스가 만나면서 `y = -0.34`의 수직 낙차면도 자동으로
생긴다. 잴 때도 그 범위 안의 팔 부분만 센서로 치므로 서로 간섭하지 않는다.

측정 원리는 **충돌 모델 자체를 자로 쓰는 것**이다. 가상 평면을 팔 쪽으로 이분
탐색해서 처음 닿는 위치를 찾는다. TCP를 읽지 않는 이유는 `TCP_OFFSET_M`이 장착되지
않은 그리퍼 길이를 담고 있어서다. 측정과 강제를 같은 모델로 하므로 자기일관적이다
— 단 **잴 때의 손목 자세를 작업할 때와 같게** 두어야 모델 그리퍼와 실제 툴의 치수
차이가 상수로 상쇄된다.

닿은 부위가 `gripper_*`가 아니면 저장을 거부한다(`--yes`로 강제 가능). 툴이 아닌
링크가 먼저 닿았다면 그 높이는 면이 아니기 때문이다.

지운다:

```bash
$T --forget-surface low_shelf
$T --forget-surface all
```

방향을 잘못 잡았을 때 `y+`를 새로 교시해도 `y-`는 **안 지워진다.** 서로 다른
면으로 취급된다.

### 3.2 작업점 p1 / p2 / home

**물건에 닿게 두지 말고 위 3~5 cm 호버**로 잡는다. 거기서부터 접촉 감지 하강이
시작된다. 기본 하강 한도가 60 mm이므로 그 안에 닿아야 한다.

```bash
$T --teach p1 --level    # 집을 물건 위 호버
$T --teach p2 --level    # 놓을 자리 위 호버
$T --teach home          # 파킹 자세. 자세 구속과 무관하므로 --level 불필요
```

**`--level`을 쓸 것.** 운반은 CBiRRT가 **출발 자세를 그대로 붙들고** 가는 것이지
"수직으로" 가는 것이 아니다. 손으로 교시하면 1~2° 기울어지기 마련이고, 그러면 그
기울기를 운반 내내 안고 간다. 게다가 p2가 그 다양체에서 벗어나 있으면 계획은
엉뚱한 곳에서 끝나고 교시한 p2까지는 **계획되지 않은 마지막 한 걸음**으로 튄다 —
이것이 "놓을 때 다시 정렬하는" 현상이고, 실측 착지 오차 8~11 mm의 정체다 (§7.1).

`--level`은 **TCP 위치는 그대로 두고 자세만 정확히 수직으로 스냅**한다. 보정은
툴 축을 수직 아래로 보내는 최소 회전이라 툴 축 둘레 회전(yaw)은 건드리지 않으므로
J6가 튀지 않는다. 손목을 0.1° 단위로 조그하는 것보다 정확하고 빠르다.

```
--level: tilt 1.40 -> 0.00 deg   joints moved 1.31 deg   TCP held to 0.02 mm
```

`TCP held`가 0에 가까워야 한다 — 툴 끝이 교시한 자리를 벗어나지 않았다는 뜻이다.
저장 뒤에는 팔의 실제 자세와 교시값이 그 `joints moved`만큼 다르다. 툴 끝 위치는
같으므로 물리적으로는 같은 곳을 가리키고, `--run`의 첫 접근에서 그만큼 손목이
돌아간다. 정상이다.

교시 직후 상대 자세도 표시된다:

```
tool attitude vs p1: 0.00 deg (OK)
```

교시할 때마다 나오는 진단:

```
joint states live (URDF convention): -184.9 -15.7 -124.9 +49.6 -89.1 -10.1
  tool  :   1.4 deg off straight-down (DOWN)
  flange: x=-0.420  y=+0.109  z=+0.076  m (base_link -- GetPose와 직접 비교 가능)
```

`flange:` 값은 로봇의 `GetPose(user=0, tool=0)`과 **직접 비교된다.** 몇 mm 이내로
맞지 않으면 부호 변환이 꺼졌거나 모델이 바뀐 것이다 (§7 참고).

확인:

```bash
$T --show
```

## 4. 실행

```bash
$T --dry                                       # 계획만, 로봇 안 움직임. 1~2분
$T --run --speed 0.15 --descend-speed 0.003 --clearance 0.12
```

`--level`로 교시했다면 완화 옵션은 필요 없다. 그러지 않아 p1/p2 자세가 2° 넘게
벌어져 있으면 `--run`이 움직이기 전에 거부하는데, 그때만 `--tilt-tol 3
--drift-tol 0.05`를 붙여 8~11 mm 오차를 감수하고 돌릴 수 있다. **임시방편이다** —
그리퍼를 달고 실제로 집을 때는 그 오차가 그대로 실패가 된다.

`--dry`가 마지막에 이 줄을 내면 통과다:

```
--dry: 1 cycle(s) planned and checked, nothing moved.
```

**반복**:

```bash
$T --run --cycles 10 --yes --speed 0.15 --descend-speed 0.003 --clearance 0.12
```

한 프로세스 안에서 반복하므로 플래너 구축(약 10초)을 한 번만 한다. 무한 반복이
필요하면 셸 루프로 감싸되 `--yes`를 붙인다. 실패하면 0이 아닌 값으로 끝나므로
`while $RUN; do ...; done`이 자동으로 멈춘다.

한 사이클은 위 설정에서 약 90초.

### 4.1 주요 옵션

| 옵션 | 기본 | 뜻 |
|---|---|---|
| `--drop` | 0.06 | 지점당 최대 하강, m |
| `--clearance` | 0.02 | 접촉 지점에서 추가로 올릴 높이, m |
| `--dwell` | 3 | 접촉 후 대기, 초 |
| `--speed` | 0.25 | 접근·운반 관절 속도, rad/s |
| `--descend-speed` | 0.005 | 하강 속도, m/s |
| `--collision-level` | 3 | 컨트롤러 충돌 감지 감도 0~5 |
| `--level` | — | 교시 시 자세를 정확히 수직으로 스냅 (§3.2). p1/p2에 쓸 것 |
| `--tilt-tol` | 2.0 | p1과 p2의 툴 자세 허용 차이, 도 |
| `--drift-tol` | 0.02 | 투영 드리프트 허용치, rad |
| `--torque-trip` | — | 소프트 임계값을 J1~J5 일괄 지정 |
| `--no-torque-trip` | — | 소프트 채널 끄기 (펌웨어 트립만) |
| `--speed-factor` | 0 | 컨트롤러 전역 속도 상한 %. **종료 후에도 남음** |
| `--yes` | — | 실행 전 확인 프롬프트 생략 |

## 5. 접촉 감지

**두 채널**이 있고 둘 다 관절 토크를 쓴다. 이 로봇에는 6축 힘 센서가 없어
(`SixForceOnline = 0`, `TCP_force` 전부 0, `GetForce()` → `res=-1`)
`SetFCCollision(force, torque)`처럼 **뉴턴 단위로 지정하는 경로는 쓸 수 없다.**

| 채널 | 누가 판단 | 특징 |
|---|---|---|
| 컨트롤러 충돌 감지 | 펌웨어 | `SetCollisionLevel(0~5)` 감도만. 최후 방어 |
| 소프트 토크 채널 | 스크립트 | N·m 임계값을 우리가 지정. 먼저, 더 부드럽게 |

소프트 채널은 **현재 토크와 0.35초 전 토크의 차이**를 임계값과 비교한다. 절대값이
아니라 변화량인 이유는 자세가 바뀌면 중력 부하가 계속 달라지기 때문이다.

### 5.1 임계값의 근거 (측정값)

허공에서 20 mm를 3 mm/s로 내려가며 매 틱 기록한 결과 (2026-08-06):

```
t < 1.2 s   출발 과도구간   J2 최대 7.27, J3 최대 12.52, J4 최대 2.57   ← 아무것도 안 닿음
t > 1.3 s   안정 구간       J1 0.20, J2 1.82, J3 1.41, J4 0.65, J5/J6 ~0
```

정지 상태에서 움직이기 시작하는 순간(정지 마찰 해제 + 가속 토크) 토크가 크게
요동친다. 이걸 판정하면 **모든 하강이 첫 밀리미터에서 트립한다** — 실제로 그렇게
됐었다. 그래서:

- **출발 후 1.5초는 소프트 채널을 아예 끈다** (`TORQUE_BLANK_S`). 그동안은
  컨트롤러 충돌 감지가 지킨다. 3 mm/s에서 4.5 mm에 해당
- **임계값은 안정 구간 노이즈의 약 2배**: J1~J5 = `1.5, 4.0, 3.5, 2.0, 1.5`.
  J6는 이 컨트롤러에서 항상 0이라 제외

### 5.2 검증 (휴지곽)

80 mm 하강, 3 mm/s:

```
 5 ~ 55 mm   J3 변화량 0.0 ~ 1.0      ← 오검출 없음
   60.5 mm   J3 1.4                   ← 물체에 닿기 시작
   65.5 mm   J3 1.6
   67.0 mm   J3 3.84 > 3.50 → 정지
```

무른 물체라 첫 접촉(약 60 mm) 이후 **7 mm쯤 눌려 들어간 뒤** 트립했다. 단단한
물체면 토크가 급격히 올라 훨씬 얕게 멈춘다.

### 5.3 속도를 바꾸면

트립 시점의 눌림 깊이는 이론상 속도와 거의 무관하다(오차도 토크도 속도에 비례해서
상쇄). 하지만 **감지 지연(기준선 0.35초 + 연속 2틱 ≈ 0.4초) 동안의 추가 이동은
속도에 비례한다**:

| 하강 속도 | 지연 중 추가 이동 |
|---|---|
| 3 mm/s | 1.2 mm |
| 10 mm/s | 4 mm |
| 30 mm/s | 12 mm |

그리고 노이즈 바닥도 속도가 오르면 함께 오른다. **위 임계값은 3 mm/s 전용이다.**
다른 속도로 쓸 거면 그 속도에서 다시 측정할 것 (§5.5).

**`SetCollisionLevel`도 같이 봐야 한다.** 펌웨어 감지 역시 같은 관절 토크를 보므로
속도가 오르면 동역학 토크가 커져 **정상 동작 중에도 트립**하기 시작한다. 반대로
빠른 이동에 맞춰 둔감하게(낮은 레벨) 잡아두면 느린 터치오프에서 물건을 세게 누른
뒤에야 선다. 하강 속도를 바꿀 때는 소프트 임계값과 `--collision-level`을 **한 쌍으로**
다시 잡을 것. 지금 값(레벨 3)은 3 mm/s 하강 + 0.15 rad/s 접근에서 확인한 것이다.

### 5.5 임계값 재측정 절차

§5.1의 숫자를 뽑은 도구가 `~/dobot_ws/check_descend.py`에 남아 있다. 소프트 채널을
끈 채로 하강하면서 매 틱의 토크 변화량을 찍는다(펌웨어 충돌 감지는 켜둔 채라
실제 위험은 그쪽이 막는다).

**아래로 25 mm 이상 여유가 있는 빈 공간**에 팔을 두고:

```bash
docker exec -it ros2_dobot bash -lc 'source /opt/ros/humble/setup.bash
source /root/dobot_ws/install/setup.bash
export DOBOT_TYPE=cr7
cd /root/dobot_ws/src/DOBOT_6Axis_ROS2_V4
/root/dobot_ws/.venv/bin/python3 /root/dobot_ws/check_descend.py --profile'
```

출력에서 읽을 것:

1. **과도구간이 몇 초 가는가** → `TORQUE_BLANK_S`를 그보다 길게
2. **안정 구간의 관절별 최대 변화량** → `TORQUE_TRIP`을 그 약 2배로

속도를 바꿔 재려면 `check_descend.py`의 `SPEED` 상수를 고친다. 거리는
`--mm N`으로 준다.

측정 뒤에는 **실물로 확인**할 것 — 휴지곽처럼 눌리는 물체를 두고 `--move`로
하강시켜서, 접촉 전 변화량이 임계값보다 충분히 작게 유지되다가 접촉에서 넘는지
본다(§5.2가 그 예다). 숫자만 보고 넘어가면 오검출을 실기에서 만나게 된다.

### 5.4 "의도한 접촉"과 "사고"는 구분되지 않는다

컨트롤러도 우리도 예상치 못한 토크가 났다는 것만 안다. 둘을 가르는 건 센서가
아니라 **맥락**이다: 교시한 지점 위에서만 하강하고, `--drop`으로 거리를 묶고,
느리게 접근하고, 등록한 면으로 울타리를 친다.

## 6. 하강을 왜 액션으로 안 보내나

`dobot_moveit/action_move_server.py`에는 cancel 콜백이 없다. 한 번 보낸 goal은
중간에 멈출 수 없는데, **접촉 시 멈추는 게 하강의 존재 이유**다. 그래서 하강만
`/dobot_bringup_ros2/srv/ServoJ`로 33 Hz 직접 스트리밍한다. 스트림을 끊는 것 자체가
깨끗한 정지다 — `ServoJ`는 "t 안에 이 목표로 가서 유지"라 마지막 목표에서 선다.

접근·운반·상승은 평범한 `execute_path` 액션으로 간다.

**이 우회 때문에 `node.py`의 부호 변환도 함께 우회된다.** `Dashboard.servoj()`가
따로 변환을 적용한다. 이걸 빠뜨렸을 때 J1에 370° 오차가 실려 팔이 급발진했다.
그 재발을 막으려고 **매 틱 안전 게이트**가 있다 — 보낼 목표가 로봇이 직접 보고하는
`q_actual`에서 5° 넘게 떨어져 있으면 전송하지 않고 중단한다.

### 7.1 툴 자세가 왜 눈에 띄나

운반 중 툴이 약간 기울어 보이고 놓을 때 다시 정렬하는 것처럼 보이는 건 정상
동작이다. 실측 경로:

```
운반 중        tilt 1.35°  (전 구간 고정)   J6 -10.1 → -12.0 → -10.1
교시된 p2      tilt 0.98°                   ← 마지막에 여기로 튐
```

- CBiRRT는 "수직"이 아니라 **출발 자세(p1의 1.4°)** 를 유지한다. 구속은 완벽히
  작동 중이고, 유지하는 값이 수직이 아닐 뿐이다
- p2는 그 다양체 위에 없으므로 계획은 근처 다른 자세에서 끝나고, 코드가 **교시된
  p2를 마지막 한 걸음으로 덧붙인다.** 그 점프가 "다시 정렬"로 보인다
- J6가 2°쯤 흔들리는 건 의도된 것이다. 구속이 툴 축 기울기만 잡고 **툴 축 둘레
  회전은 자유**로 두어야 다양체가 4자유도가 되어 CBiRRT가 잘 풀린다

## 9. 문제가 생기면

```bash
$S --status        # 노드 중복 + 로봇 모드·에러·충돌 상태
$S --clear-error   # 충돌 트립/알람 해제 (움직이지 않음)
$T --monitor       # 6축 토크·모드 실시간. 로봇에 명령 안 보냄
```

| 증상 | 원인 |
|---|---|
| 팔이 튀고 충돌 트립 | 액션 서버 중복 (`--status`에 `UP x2`) |
| 하강이 첫 밀리미터에서 트립 | 출발 과도구간. 블랭킹이 꺼졌거나 임계값이 낮음 |
| 조그 후 스틱 건드리면 확 달림 | `jog_action.py`의 목표 누적 — 수정됨. 옛 프로세스가 돌고 있으면 재시작 |
| `flange:`가 `GetPose`와 크게 다름 | 부호 변환 문제. `real_robot_joint_convention.md` |
| `taught goal is N rad off the tilt manifold` | p1/p2 자세 차이. §7.1 |
| `ABORT: next target is N deg from where the arm actually is` | 안전 게이트. 규약/프레임 버그이므로 원인을 찾을 것 |
